# exam-hwpx [기계] 검사 레지스트리

> 이 스킬이 가진 [기계] 검사 전체다. 정본은 코드다: 원고 규칙 `exam_kit/lint.py`(E·W) · 원고 문법 `exam_kit/scan.py`(E001로 모인다) · 조판본 `exam_kit/verify.py`·`exam_kit/build.py`(M) · 렌더 루프 알림 `exam_kit/layout.py`(settle 끝의 재검사). 코드가 바뀌면 이 표를 함께 고친다.
>
> - 통과 보고는 **"기계 잔존 N"까지만**이다. 판정은 사용자 검수다. 애매하면 [의미]다.
> - 이 목록 밖의 즉석 검사 스크립트로 PASS를 판정 근거로 쓰지 않는다.

## 1. 원고 규칙 검사 — `uv run python -m exam_kit.lint <원고.md>`

E = 오류(`build`가 조판을 거부한다, `--lint-warn`이면 경고로 두고 조판). W = 경고(보고만). `build` 보고서의 "규칙 검사" 절에도 같은 목록이 나온다.

| 코드 | 검사 | 무엇까지만 [기계]인가 — 나머지는 [의미] |
|---|---|---|
| E001 | 문법: 귀속 불가 줄·모르는 펜스/문항 지시·닫히지 않은 펜스·코드 블록·문항 앞 본문 등 | 원고가 문법에 맞는지까지 |
| E002 | 문항 번호가 1부터 빠짐없이 차례대로 | 번호 순번까지 |
| E003 · W003 | 배점 없음(E) · 옛 `(N점)` 표기(W, `[N.N점]` 권장) | 표기 존재까지. 배점 배분의 타당성은 [의미] |
| E004 | 배점 합 = 만점(머리 `만점`, 기본 100) | 산술까지 |
| E005 | 문항마다 정답 `*` 정확히 1개 | 표기 개수까지. **정답이 맞는지·복수 정답 가능성은 [의미]** |
| W005 | 초안(머리 자리표시 또는 `--draft`)에서 정답 표기 없는 문항 — 한/글 초안을 되돌린 원고에 흔하다. 답 표시본에 그 문항 형광펜이 없다(M8 [W]). 최종판은 E005 | 표기 있음까지 |
| E006 | 답지가 ①~⑤ 다섯 개, 차례대로 | 원문자 차례까지 |
| E007 · W007 | 정답 번호 편중(한 번호가 ⌈문항 수 ÷ 3⌉ 초과, E) · 번호별 개수가 전부 같음(W) | 분포 산술까지(정답 5개 미만이면 보지 않는다) |
| E008 | 블록 순서 자료·표·그림·코드 → 〈보기〉 → 답지(발문 이음 줄은 바로 위 블록에 딸려 따지지 않는다) | 순서까지 |
| E009 | 답항표에 `머리`가 있고 다섯 행, 행마다 칸 수 = 머리 수 | 모양까지 |
| E010 | 그림 파일이 있다(자료 박스 안·세트 블록 포함) | 파일 존재까지 |
| E011 | 세트 `## a~b. 세트`의 문항이 a..b 전부, 2개 이상 | 번호 구성까지 |
| E012 | 발문의 `[a~b]` 물결 — `∼`(U+223C)를 쓴다 | 글자 모양까지 |
| E013 | 〈보기〉 항목이 `ㄱ.`~`ㅁ.` 또는 `∘`로 시작, `(1)` 꼴 금지 | 항목 기호까지 |
| E014 | 발문 금칙 어휘: 적합하다·적당하다·올바르다(관형형 포함, `부-` 제외) · 거리가 먼 · 가깝지 않은 · 깊지 않은 | 낱말 존재까지. **어휘가 적절한지는 [의미]** |
| E015 | 부정 발문(직접 발문 끝 문장)에 '가장' | 낱말 존재까지 |
| E016 | 발문에 `**굵게**` · 부정어(않은·않는·아닌·없는·틀린)에 `__밑줄__` 없음 | 표기 존재까지 |
| E017 | `다음 〈보기〉`·`다음 그림`·`다음 표`·`다음 그래프` — '다음'은 박스 자료에만 | 문자열 존재까지 |
| E018 | '위 글' → '윗글' | 문자열 존재까지 |
| W019 | 답지가 길이순도 기호순도 아님(답항표 문항 제외) | **순서 위반 존재까지만** — 논리순인지는 [의미] |
| W020 | 직접 발문이 `?`로 끝나지 않음 | 끝 글자까지 |
| E021 | 1번 문항에 `{단나눔}`·`{쪽나눔}` | 지시 위치까지 |
| E024 | 답지·〈보기〉·자료·답항표·세트 지문 글에 `**`(코드 블록 안은 제외) — 조판에서 별표가 그대로 찍힌다(발문은 E016) | 표기 존재까지 |
| E026 | 보존 블록(`## 보존` 아래 `:::보존 src=…`)의 원본 구간 hwpx가 원고 옆에 없다 — 없으면 그 구간이 조판에서 빠진다 | 파일이 있는지까지 |
| E025 | 수식 `$…$` 표기: 닫히지 않은 `$` · 빈 수식 · 블록 수식 `$$…$$`(아직 조판하지 않는다) · 한/글 수식으로 바꿀 수 없는 LaTeX(변환기 까닭을 붙인다). 조판에 들어가는 모든 글(코드 블록·그림 줄 제외) | 변환 가능까지. **수식이 맞는지·보기 좋은지는 [의미]** |
| W022 | 그림을 줄여 넣음(원고 폭 < 원래 크기 × 0.98, 원래 크기 = px ÷ 300dpi) | 치수 산술까지. 그림이 읽히는지는 [의미](100% 육안·인쇄본) |
| W023 | 그림을 늘려 넣음(원고 폭 > 원래 크기 × 1.02 — 300dpi 아래) | 치수 산술까지 |

조판 단계의 그림 폭 초과(단 10.9cm, 자료 박스 안 약 10.1cm)는 검사 코드가 아니라 조판 오류로 멈춘다.

수식 `$…$` 안의 글자는 학교 규칙의 정규식에 넣지 않는다(E013 항목 기호의 `(1)`, E016·E024의 `**` — 수식 안의 `f(1)`·`a^{**}`는 LaTeX다). W019의 답지 길이는 원고 글 길이(수식은 LaTeX 글자 수)로 센다.

## 2. 조판본 검사 — `build`가 두 판마다 돈다

보고서 "기계 검사" 절에 `기계 잔존 N`(E 수)으로 나온다. `build` 끝 코드 0 = 두 판 모두 기계 잔존 0.

|---|---|---|---|
| M6 | 패키지 `validate()` 통과 | 두 판 | 스키마 검사까지. 한글이 손상 경고 없이 여는지는 렌더(`render.check_package` + 실한컴)가 보고, 안 열리면 조판이 멈춘다 |
| M7a | 본문 빈 최상위 문단 0 | 두 판 | 개수까지 |

| M7d | 양식 안내·샘플 문구 잔존 0 | 두 판 | 금지 문구 목록(`prepare.금지_문구`)까지 |

| M10 | 렌더 쪽수 = 총쪽수 누름틀(= 문항지 쪽수) · 본문 없는 쪽 0 · 꼬리 박스가 마지막 쪽 오른쪽 단에, 제자리 윗선에, 글자와 안 겹침 | 두 판 | 기하까지. 꼬리 박스 위 여백이 보기 좋은지는 [의미] |
| M11 | 답 표시본에서 뽑은 정답 = 원고 `*` | 답 표시본 | 대조까지. 형광펜은 한컴 PDF에 그려지지 않아 hwpx에서 뽑는다 |

## 3. 렌더 루프의 최종 재검사 — 보고서 "확인 필요"

`settle` 끝에서 마지막 렌더를 다시 본다. **기계 잔존 수에 들지 않는 알림**이므로 보고서의 "확인 필요"를 반드시 읽는다.

| 알림 | 검사 | 무엇까지만 [기계]인가 |
|---|---|---|
| 최종 렌더에 문항 분할이 남았다 | 기하 분할 검사(설계 U-7): 글리프 곡선 bbox로 각 단 맨 윗줄이 문항 머리 자리에서 시작하는지 | 분할 존재까지. 한 단보다 긴 문항은 풀 수 없다고 알린다 |
| 최종 렌더의 꼬리 박스가 제자리가 아니다 | 빈 쪽·글자 침범 | 기하까지 |
| 최종 렌더에 접힌 답지 줄이 남았다 | 답지 탭 칸 넘침·줄 접힘 | 기하까지. 배치형이 보기 좋은지는 [의미] |
| 자간 하한까지 줄여도 못 당긴 발문 | 줄 캐시 대조 | 줄 수까지 |
| 꼬리 박스 자리 때문에 간격을 줄였다 · 문항을 다음 쪽으로 넘겼다 · 나눔 지시가 있어 옮기지 않는다 | 꼬리 박스 자리 판정(설계 R-5) | 사실 보고까지. 넘긴 배치가 괜찮은지는 [의미] |
| [쪽 추가] · 총쪽수를 채웠더니 쪽수가 바뀌었다 · 간격 나눔 되돌림 · 균형 배치 되돌림 | 루프가 목표를 못 이룬 경우 | 사실 보고까지 |

## 4. 원본 재현 줄 대조 — `python -m exam_kit.fit`

엔진 문항지와 기준본(제출본)의 문단별 줄 수·줄 시작(앞의 공백 아닌 글자 수)을 대조하고, 불일치마다 까닭을 붙인다. 두 관점을 늘 함께 낸다: ① 기준본을 이 PC 한컴으로 새로 조판한 줄(합격 기준: **설명 없는 불일치 0**, 끝 코드 0) · ② 기준본 저장 줄 캐시(출제 PC). 까닭 분류와 불일치 존재까지만 [기계]다 — 달라진 곳이 나아진 것인지 틀린 것인지는 사용자 검수.

## 5. [의미] — 서면, 판정자 사용자

원본 재현 충실도 · 간격·정렬·박스 모양 · 실물 사용성(냉정 통독·쪽별 좌우 PNG·B4 출력) · 그림 농도와 선명도 · 문항 내용 일체(내용 스킬 소관).
