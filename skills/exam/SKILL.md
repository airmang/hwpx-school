# exam — 원안지 hwpx 조판 (학교 무관)

원안지 한 파일은 결재 서류·학생 문항지(B4 2단)·정답 기록(정답 원문자에 노랑 형광펜)을 겸한다. 바탕은 **학교 서식 hwpx 그 파일**이다. 조판 때마다 서식을 열어 학교 안내가 지우라는 것만 지우고, 머리 값을 채우고, 서식의 샘플 문항 구역을 문항으로 바꾼다. 〈보기〉·〈조건〉·자료 박스는 서식 안의 견본을 복제한다.

학교마다 다른 것은 전부 **학교 킷**에 있고, 학교 킷은 **이 제품 저장소에 없다** — 각 사용자가 자기 학교를 등록해 자기 PC에 만든다(폴더 하나 = 학교 하나). 엔진(`exam/exam_kit`)에는 학교 문구·치수가 없다.

| 킷 파일 | 층 | 담는 것 |
|---|---|---|
| `kit.json` | 양식 | 용지·단·스타일 역할·머리 값 자리(누름틀 `slots` 또는 글자 자리 `text_slots`)·관리박스 정리·지울 구역·견본 박스·번호 방식·조판 관례·글자 폭·렌더 판정·꼬리 박스 |
| `rules.json` | 학교 규칙 | 학교 문항 제작 규칙의 [기계] 검사(없으면 엔진 규칙만) |
| `habits.json` | 교사 습관 | 간격·자간 맞춤·〈보기〉 내어쓰기(없으면 엔진 기본 = 첫 등록 학교 1학기 실측) |
| `README.md`·`결정표.md` | 기록 | 값의 근거·개정 이력·등록 결정 |
| `SKILL.md` | 학교 스킬 | 그 학교 서식 위치·sha·그 학교만의 주의 — 이 범용 스킬을 가리킨다 |

사용자가 학교 원안지를 요청하면 먼저 그 학교 킷 폴더의 `SKILL.md`를 찾아 읽는다(서식·킷 경로). 없으면 그 학교는 아직 등록되지 않았다 — 등록부터 한다.

저장소에는 **합성 킷 `exam/kits/synthetic`**(학교 무관 합성 서식 `synthetic_form.hwpx` + 킷)만 있다 — 엔진 테스트·킷 모양의 예·시연용이고, 실제 학교 시험지에는 쓰지 않는다. 합성 서식은 `exam/tools/make_synthetic_form.py`가 python-hwpx 기본 템플릿에서 만든다.

## 명령 (엔진 폴더 `exam/`에서)

    uv run python -m exam_kit.lint <원고.md> --kit <학교 킷 폴더>
    uv run python -W ignore -m exam_kit.build <원고.md> --kit <학교 킷 폴더> --form "<서식.hwpx>" --out <미추적 경로>/<이름> [옵션]

| 옵션 | 뜻 |
|---|---|
| `--draft` | 미확정 머리 값(`__`·`_`)을 오류가 아닌 경고로. 원고 머리에 자리표시가 있으면 저절로 초안이다 |
| `--lint-warn` | 규칙 검사 오류가 있어도 조판한다(보고서 맨 앞에 **[규칙 오류 무시]**) |
| `--gap distribute` · `fixed` | 없으면 킷 `habits.json`의 `gap_mode`(단 아래 맞춤 / 한 줄 고정) |
| `--pack balanced` · `greedy` | 없으면 킷 `habits.json`의 `pack` |
| `--compare <제출본.hwpx>` | 쪽별 좌우 대조 PNG |
| `--stage "<문구>"` | 보고서 맨 위 단계 줄 |

- `build` 순서: 규칙 검사 → 서식 준비·머리 값 → 조판 → 렌더 루프(접힌 답지 → 자간 맞춤 → 균형 배치 → 분할 → 단 맨 위 간격 → 꼬리 박스 → 간격 나눔 → 총쪽수) → 답 표시본(같은 파일 + 형광펜) → [기계] 검사 → `보고.md`.
- 끝 코드: `0` 기계 잔존 0 · `1` 규칙 오류로 조판 안 함 · `2` 기계 잔존 있음. 보고서의 **확인 필요**는 반드시 읽는다(기계 잔존 수에 들지 않는다). 보고서 머리에 교사 습관값·학교 규칙의 출처가 찍힌다.
- 역변환(한/글에서 만든 원안지 `.hwp`·`.hwpx` → 원고 md): `uv run python -m exam_kit.reverse <원안지> --kit <학교 킷 폴더> --out <미추적 경로>/원고.md [--front 키=값 …]`.
  - **학교 킷이 없으면** `--kit`을 빼고 돌린다 — 일반 규칙으로 읽는다(차례대로 이어지는 문항 번호, 제목 글로 찾는 〈보기〉·〈조건〉, 글 칸 하나뿐인 표 = 자료, `※` 안내 상자 = 꼬리, 첫 문항 앞 글·머리말에서 머리 값). 추정이므로 원고를 한 번 훑어본다. 그 학교를 자주 쓰면 등록(킷)한다.
  - `.hwp`는 python-hwpx로 연다. 바꾸지 못한 내용이 있으면 멈춘다 — 한/글에서 hwpx로 저장해 다시 넣는다.
  - 그림은 원고 옆 PNG로 꺼내고 자리(가운데 / 단 왼쪽 + 띄움 `align=left indent=…`)도 되살린다. 수식은 `$LaTeX$`로 되돌린다.
  - 문서에서 읽지 못한 머리 값(누름틀이 없거나 비었다)은 멈추고 `--front 학년=… 과목=…`처럼 줄 키를 알린다.
  - 서술형·논술형 구간(아직 조판하지 않는다)은 **보존 블록**이다. 원본 모양 그대로 `보존_01.hwpx`로 떼어 원고 끝 `## 보존` 아래에 둔다. 조판이 그 자리(문항 뒤·꼬리 박스 앞)에 다시 심는다. 그 글은 원고에서 고치지 않는다(한/글에서 고친다).
  - 모르는 구조는 조용히 넘기지 않고 멈춘다. 문항·쪽 어림·문단·까닭을 알린다.
  - 정답 형광펜이 없는 초안도 멈추지 않는다 — 정답 없는 문항을 알리고 `*` 없이 쓴다. `--draft`로 조판하면 경고(W005·M8 [W])로 두고, 최종판은 정답 표기가 문항마다 하나여야 한다(E005).
- 작은 수정(막바지 오탈자·숫자·표현·정답 바꾸기): 원고를 고치고 `uv run python -W ignore -m exam_kit.patch <고친 원고.md> --prev <기존 산출 폴더> --kit <학교 킷 폴더> --form <서식.hwpx> --out <새 폴더>`. 고친 글만 기존 두 판에 갈아 끼우고 쪽·단 나눔·배치형·간격·자간은 그대로 둔다. 문항·블록·발문 문단·답지 수, 그림, 머리 값, 배점 합이 바뀌었거나 렌더에서 문항 머리가 하나라도 움직였으면(글자 폭이 늘어 줄이 늘어나는 등 — 완성된 시험지는 단 아래까지 간격이 차 있어 한 줄도 여유가 없다) 끝 코드 3 '다시 조판 필요' — `build`로 다시 뽑는다. hwpx를 직접 고치지 않는다.
- 왕복 불변 검사(역변환 합격): `uv run python -m exam_kit.roundtrip <원안지> --kit <학교 킷 폴더> --form <서식.hwpx> --work <미추적 경로>`. 킷 없는 원안지는 `--generic --kit kits/synthetic --form kits/synthetic/synthetic_form.hwpx`(합성 킷 위에 다시 조판해 견준다). 끝 코드 0 = 같다. 다른 곳은 자리만 알리고 문항 글은 쓰지 않는다 — 실제 원안지 결과는 수치만 공유한다.
- 지필 원고(문제지·정답키 형식) 변환: `uv run python -m exam_kit.convert "<원고.md>" --out <미추적 경로> --kit <학교 킷 폴더> [--figures …] [--front 키=값 …]` — 문항 내용 불변 검사가 안에 있다.

## 새 학교 등록 — `references/학교-등록.md`

빈 원안지 서식 한 장이면 된다. ① `onboard scan`(해부) → ② 스킬이 역할을 제안 → ③ 사용자 결정표(항목별) → ④ `onboard draft` + 결정대로 킷 채움 → ⑤ 서식 준비·합성 원고 조판 테스트 → ⑥ 사용자 검수(서식 준비·유형별 견본) → 학교 스킬 문서(킷 폴더의 `SKILL.md`). **학교를 더할 때 파이썬이 늘면 설계 실패 신호다** — 킷 값으로 안 되는 것이 나오면 엔진을 일반화하고(기존 학교 회귀 통과가 조건), 그 학교만의 분기를 넣지 않는다.

## 문법 (`references/문법.md`)

머리(키는 킷 `front_matter`가 필수·선택을 정한다 — 조판 지시 `답항: 1행부터`는 어느 킷에서나) · `## N. [3.8점]` 머리(끝에 `{답항=2행}`·`{단나눔}`·`{쪽나눔}`) · 발문 평문, 부정어는 `__않은__` · 인라인 수식 `$…$`(LaTeX, 달러 글자는 `\$`) · `:::자료` · `:::보기` · `:::조건`(킷에 견본이 있을 때) · 펜스 밖 md 표 · `![](그림.png){width=10.0cm}` · ```` ``` ```` 코드 블록 · 답지 `①`~`⑤` 한 줄에 하나, 정답 앞 `*` · 짝짓기 `:::답항표 머리="ㄱ|ㄴ|ㄷ"` · 세트 `## 7~8. 세트` + 지문 + `### 7.`. 출제교사 여러 명은 쉼표로(쓴 차례대로 찍힌다).

## 절대 규칙

- **사용자 검수.** 형태 판정은 사용자 몫이다. 게이트에 올리는 조건은 기계 잔존 0 + 볼 실물의 **절대 경로와 `open` 명령** + 내가 본 차이 메모다. 판정은 사용자의 말 그대로 기록한다. 지적은 엔진·킷·원고를 고쳐 다시 뽑고 같은 게이트에 다시 올린다.
- **"기계 잔존 N"으로만 쓴다.** PASS를 "검증 완료"·"제출 가능"으로 쓰지 않는다.
- **산출물 손편집 금지.** 고칠 것은 원고·킷·엔진에서 고친다.
- **보안 위치.** 실문항이 든 파일(원고 md, 산출 hwpx·pdf·png, 역변환 md, 대조 자료)과 **학교 서식 원본**은 git 미추적 위치에만 둔다(사용자가 정한 로컬 폴더). 저장소에는 킷(sha·수치·규칙)과 합성 문항만. 스크래치·커밋·보고서·테스트에 실문항 글을 쓰지 않는다. 문항을 외부 서비스로 보내지 않는다.
- **엔진 회귀.** 엔진이나 python-hwpx를 바꾸면 등록된 모든 학교의 기준 산출물로 회귀를 돌린다: `uv run python -m exam_kit.gate <기준 폴더> <새 폴더>`(끝 코드 0 = 같다). 같다고 보는 차이는 둘뿐이다 — `<hp:p id>`·그림 instid(python-hwpx가 빌드마다 바꾼다)와 paraPr의 id·개수(내용이 같으면 같은 paraPr로 본다 — python-hwpx 6.6.0부터 같은 내용의 paraPr를 재사용한다). header의 paraPr는 내용의 집합으로, paraPrIDRef는 그 내용으로 견주고 나머지는 바이트까지 같아야 한다.
- **한컴은 공용 자원이다.** 렌더·줄 캐시 저장은 사용자별 공용 잠금(`hwpx_automation…mac_session._gui_lock_path()`) 안에서만(엔진이 잡는다). 오래 쓸 때는 다른 세션에 먼저 알린다. 남의 창·대화상자는 건드리지 않는다. 렌더 전 zip 검사(`render.check_package`).
- **pytest `-m`은 addopts의 `-m`을 덮어쓴다** — 실렌더 테스트를 빼려면 이 프로젝트는 `-m "not render"`(worksheet·assessment는 `-m`을 주지 않는다).
- 문항 **내용** 판정은 내용 스킬 소관이다. 이 스킬은 표기(문법)만 맞춘다.

## 하지 않는 것

논술형 블록·채점기준표 · 문항정보표 · 반별 이형 · 블록 수식 `$$…$$`(인라인 수식만 한다) · 문항 내용 판정 · 공개 배포(학교 서식이라 로컬 전용).
