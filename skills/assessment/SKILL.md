# assessment — 수행평가 문제지 hwpx 조판 (학교 무관)

엔진·문법 정본: hwpx-school `assessment/`(README·문법). 작업 전에 문법을 읽는다.

## 킷 — 학교 킷은 저장소 밖

- 양식마다 다른 것(스켈레톤·스타일 ID·폭·득점표 문구·글꼴 옮기기)은 **학교 킷**이 갖는다. 학교 킷은 제품 저장소에 없다 — 각 사용자가 자기 PC에 만든다(폴더 하나 = 킷 하나, 그 안의 `SKILL.md`가 그 킷의 경로·검증된 예시·주의를 적는다).
- 사용자가 수행평가지를 요청하면 먼저 그 사용자의 수행평가 학교 킷 폴더의 `SKILL.md`를 찾아 읽는다. 없으면 킷부터 만든다.
- 저장소의 `assessment/kits/standard`는 **씨앗 킷**(빈 스켈레톤 + 값)이다. 새 양식으로 킷을 만들려면 이 폴더를 자기 킷 폴더로 복사하고, 그 양식 원본에서 스켈레톤을 뽑는다:
  `uv run --python 3.13 python scripts/뽑기_스켈레톤.py <원본 양식.hwpx> <킷 폴더>` — 킷의 `fontMap`(원본 글꼴 → 배포 환경 글꼴)을 적용해 `skeleton.hwpx`를 쓴다. 스타일 ID·폭·높이는 그 양식 실측으로 맞춘다(`standard` 킷 README의 값 설명).

## 명령 (엔진 폴더 `assessment/`에서)

    uv run --python 3.13 python -m assessment.cli compose <md 절대경로> --kit <학교 킷 폴더> -o <이름.hwpx 절대경로>
    uv run --python 3.13 python -m assessment.cli check   <md 절대경로> --kit <학교 킷 폴더> --out <이름.hwpx 절대경로>

- `<이름>_학생용.hwpx`·`<이름>_정답용.hwpx` 두 파일이 나온다. 종료코드 0 통과 · 1 검사 문제(JSON `"문제"`) · 2 입력 오류.
- 글꼴은 스켈레톤을 뽑을 때 킷 `fontMap`으로 이미 옮겨져 있다 — compose 는 fontMap 을 읽지 않는다. `fontMap`을 바꾸면 스켈레톤을 다시 뽑아야 반영된다.
- 2단 쪽·단 나눔은 실한컴 렌더로만 보인다 — 조판 뒤 **전 쪽**을 렌더해 눈으로 보고, 문항이 어색하게 쪼개지면 `:::단나눔` 을 넣는다. **내용을 조금이라도 고친 뒤에는 반드시 다시 전 쪽을 렌더해 눈으로 확인한다** — 검사([기계]) 통과는 형태 일치가 아니다:
  `uv run --python 3.13 python -c "from pathlib import Path; from assessment.render import render_hancom; print(render_hancom(Path('<hwpx>'), Path('<png>')))"`
  - 한글이 꺼져 있으면 자동 렌더가 한글을 띄우지 못해 "렌더 실패"로 끝날 수 있다 — 한글을 열고 다시 돌린다. 렌더는 한 번에 하나씩(공용 한컴은 다른 세션과 나눠 쓴다).
  - 렌더 출력 `<png>` 는 평범한 폴더 밑에 둔다 — `/private/tmp` 밑으로는 한컴이 PDF 를 저장하지 못한다.
- 산출물은 그 수행평가의 자료 폴더에 둔다(엔진 폴더·저장소 안에 두지 않는다).
- pytest: `-m`을 주지 않는다(addopts가 한컴 테스트를 뺀다).

## 문법에서 자주 쓰는 손잡이

- 그림 캡션: `![캡션](a.png){width=8cm caption=left}` — 기본은 가운데 정렬, `caption=left` 로 왼쪽 정렬. `width`·`caption` 둘 다 생략 가능.
- 밑줄 답칸(`:::답칸`): 밑줄이 글꼴·공백 수에 기대지 않고 **칸을 꽉 채운다** — 라벨만 적으면 된다.
- `:::단나눔`: 쪽·단 경계를 피할 때, 또는 한 문항을 통째로 한 단에 모으고 싶을 때 그 문항 바로 앞에 놓는다. 실물마다 렌더로 확인해 가며 조정한다.
- 병합 머리 표: 마크다운 표 칸에 `<`(왼쪽 칸과 합침)·`^`(위 칸과 합침). `|---|` 위 행은 몇 줄이든 음영 머리다. 첫 칸의 `<`·`^`, 직사각형이 아닌 병합은 줄 번호 오류다.
- `:::나란히`: 그림 줄 2~3개를 한 행에 같은 폭으로, 캡션은 각 그림 아래. `width` 가 칸 안쪽 폭보다 크면 입력 오류.
- 문항 밖 블록: 첫 문항 앞과 묶음을 닫은(`::::`) 뒤에는 `:::안내`·`:::제시문`·`:::조건`·그림·자료표·`:::나란히`·`:::단나눔` 만 둘 수 있다. 답칸·서술칸·정답·일반 줄은 문항 안에서만.
- 여러 줄 블록(`:::제시문`·`:::조건`·`:::정답`·`:::표답칸`) 안의 빈 줄은 조용히 사라진다 — 문단마다 한 줄씩 이어 쓴다.

## 하지 않는 것

- 문항 내용 판정 — 내용 스킬 소관.
- 학교 킷·양식 원본·학교 이름을 저장소나 공개물에 넣는 것.
- docx·구글 문서 — 2단계(아직 없음).
