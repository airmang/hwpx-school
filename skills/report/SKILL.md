# report — 보고서·계획서 hwpx (학교 무관)

서식은 **견본**이 정한다. 견본은 한/글로 저장한 문서에 `{{자리표시}}`를 적은 것이고, 엔진은
자리표시가 든 문단·표를 통째로 복제해 글만 바꾼다. 색·글꼴·선·들여쓰기를 이 스킬이나 파이썬이
정하지 않는다.

## 킷 — 학교 킷은 저장소 밖

- 저장소의 `report/kits/standard`는 **씨앗 킷**이다(합성, 남색 띠). 사용자가 자기 학교·교육청
  서식을 원하면 그 서식으로 견본을 만들어 **자기 PC의 킷 폴더**에 등록한다(아래 「견본 등록」).
- 사용자가 계획서를 요청하면 먼저 그 사용자의 보고서 킷 폴더를 찾는다. 없으면 씨앗 킷으로 만들고,
  자기 서식이 있는지 묻는다.
- 산출물·계획 JSON은 그 업무 폴더에 둔다(엔진 폴더·저장소 안에 두지 않는다).

## 명령 (엔진 폴더 `report/`에서)

    uv run python -m report_kit roles <킷 폴더>                       # 킷이 아는 역할과 칸
    uv run python -m report_kit make <계획.json> --kit <킷 폴더> -o <hwpx>
    uv run python -m report_kit register <견본.hwpx> <킷 폴더>         # 견본 → 킷

- 종료코드 `0` 통과 · `1` 조립 실패(JSON의 `errors`를 읽는다). `warnings`의 `MARKED_SLOT_EMPTY`는
  값을 주지 않은 칸이다 — 빈칸으로 나간다.
- 만든 뒤 반드시 실한컴으로 렌더해 눈으로 본다(공용 한컴: 한 번에 하나, 다른 세션 창은 건드리지 않음).
  기계 검사 통과는 "기계 잔존 0"일 뿐 제출 가능이 아니다.

## 계획 JSON

```json
{"blocks": [
  {"role": "표제", "values": {"위": "｢2026학년도 ○○｣", "아래": "○○ 운영 계획"}},
  {"role": "날짜", "text": "2026. 11."},
  {"role": "쪽나눔"},
  {"role": "띠", "values": {"번호": "Ⅰ", "제목": "추진 개요"}},
  {"role": "1단계", "text": "추진 근거"},
  {"role": "2단계", "text": "2026학년도 학교교육계획"},
  {"role": "3단계", "text": "세부 내용"},
  {"role": "참고", "text": "참고 사항"}
]}
```

- 역할 이름과 칸 이름은 킷마다 다르다. `roles`로 확인하고 그대로 쓴다.
- `text`는 이름 없는 칸(또는 칸이 하나뿐인 역할)을 채운다. 칸이 여럿이면 `values`.
- 부호(□ ㅇ - ※)는 견본에 이미 있다. `text`에 다시 쓰지 않는다.

## 문서의 짜임 — 읽는 사람이 묻는 순서대로

결재하는 사람은 "왜 하나 → 무엇을 하나 → 언제·누가·얼마로 하나 → 그래서 무엇이 나아지나"를
묻는다. 장은 이 순서를 따르되, 사안에 필요한 장만 둔다. 빈 장을 일반론으로 채우지 않는다.

- **추진 계획**: 추진 개요(근거·목적) → 세부 추진 계획(기간·대상·내용) → 추진 일정 → 소요 예산 → 행정 사항
- **결과 보고**: 개요(근거·기간·대상) → 추진 결과(실적·수치) → 성과와 보완점 → 향후 계획
- **개선 방안**: 현황 및 문제점 → 개선 방안 → 추진 일정 → 기대 효과

장끼리 이어져야 한다.
- 근거는 사실로 쓴다: 공문 번호와 날짜, 계획 이름, 법령 조항, 수치. 분위기로 여는 문장("급변하는 교육 환경에 따라")은 근거가 아니다.
- 문제점마다 방안이 짝을 이룬다. 짝 없는 문제점이나 근거 없는 방안을 남기지 않는다.
- 방안·일정에는 대상·수량·기한이 있다.
- 기대 효과는 앞에서 든 지표의 목표치로 쓴다("참여 교원 12명 → 30명"). "만족도 향상"만으로는 판단 근거가 되지 않는다.

**수치·이름·날짜는 지어내지 않는다.** 사용자가 주지 않은 값은 `○○명`, `2026. ○. ○.`처럼
자리를 비워 두고, 채울 곳을 사용자에게 알린다.

## 문장 — 개조식

- 한 항목에 한 가지만 쓴다. 항목은 명사형이나 "-함/-임"으로 끝낸다("사례 공유", "수업 공개를 운영함").
- □는 장 안의 묶음 이름(짧은 명사구), ㅇ는 그 내용, -는 ㅇ의 세부, ※는 단서·참고다. 단계를 건너뛰지 않는다.
- 날짜는 `2026. 11. 3.(화)`, 시각은 24시각 `15:00`, 기간은 `2026. 11. 3. ~ 11. 28.`로 쓴다.
- 금액은 숫자에 쉼표를 찍고 단위를 붙인다(`1,200,000원` 또는 `120만 원`). 한 문서 안에서 한 가지로 맞춘다.

## 견본 등록 — 학교·교육청 서식을 킷으로

1. 서식이 잘 된 실제 문서를 한/글로 연다. 사본에서 작업한다.
2. 남길 것만 남긴다: 제목표, 날짜, 장 제목 띠 하나, □·ㅇ·-·※ 문단 하나씩. 나머지는 지운다.
3. 글을 자리표시로 바꾼다. 부호와 앞 공백은 남긴다.
   - 문단: `□ {{1단계}}`, ` ㅇ {{2단계}}`
   - 표: 번호 칸 `{{띠.번호}}`, 제목 칸 `{{띠.제목}}` (점 앞 = 역할, 점 뒤 = 칸)
   - 표지 다음 쪽 나눔이 필요하면 쪽 나눔이 걸린 빈 문단에 `{{쪽나눔}}`.
4. 한/글로 저장한 뒤 등록한다: `uv run python -m report_kit register <견본.hwpx> <내 킷 폴더>`.
5. 씨앗 킷의 `예시_계획.json`을 역할 이름만 맞춰 `make` → 실한컴 렌더 → 원본과 나란히 비교한다.

규칙:
- 자리표시가 든 최상위 문단(또는 표 하나) = 역할 하나. 한 문단에 두 역할을 섞지 않는다.
- 역할 바로 **위의 빈 문단**은 그 역할에 딸려 함께 복제된다 — 항목 사이 간격을 견본에서 그대로 정한다.
- 자리표시가 없는 글 문단은 버려진다(`ignoredStaticParagraphs`). 남기고 싶으면 역할로 만든다.
- 역할 안에 그림은 넣지 않는다(로고는 지금 지원하지 않는다).
- 첫 구역만 읽는다. 구역이 여럿이면 첫 구역으로 모은다.

에이전트가 견본을 대신 만들 때는 원문 사본에서 문단을 지우고 자리표시를 넣는 편집만 한다.
원문 문서·학교 이름은 저장소나 공개물에 넣지 않는다.

## 이 스킬이 하지 않는 것

- 기안문(결재란·수신·발신) — 그것은 기안문 장르다.
- 표 데이터 행을 늘리는 것 — 지금 역할은 모양이 고정된 표만 복제한다.
- 서식 값을 지어내는 것. 색·글꼴이 마음에 들지 않으면 견본을 한/글에서 고친다.
